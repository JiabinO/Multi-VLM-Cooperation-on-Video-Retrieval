# EXP-001：多 VLM 协作冗余的首轮现象验证

状态：待数据检查和实现，尚无结果。详细讨论保存在个人研究笔记中。

## 为什么做
确认多端视频协作中是否存在无新增价值的重复事实，并判断删除后是否影响回答和证据。
重复信息可能是有价值的独立确认，因此不能只靠句子相似度决定删除。

## 起步方案
优先检查室内多摄像头小样本。CITIC-MTMC、MMPTrack 是此前聊天候选，尚未完成本轮访问、同步、标注与使用条件核查。
各端独立看分配的视频并输出证据卡，中心端汇总回答。首版允许端点看到问题，先保存全部原始输出。
单机多个独立模型调用可模拟端点，但不能因此声称验证了真实设备网络性能。

## 对照
- A：单端，分别报告各视角表现。
- B：多端独立回答；投票若使用，单列规则与结果。
- C：自由文本汇总。
- D：结构化证据汇总，保留全部内容。
- E：使用 D 的相同端输出，按简单规则合并重复，再重放中心回答。
- F：人工审核删除无新增复述，作诊断参考，不称严格最优上界。

先跑 A–D，再做 E/F。真实不同视角与“多个端看同一视频”的受控条件分开。
主要通过 D/E/F 判断删除的影响，避免把格式变化当作去重收益。

## 记录与评价
证据记录摄像头、时间、实体、事实、支持片段、端点、接收方、顺序、消息编号及成本。
标注新信息、无新增复述、独立确认、互补、纠错或冲突、无关或无法判断；一条消息可有多种事实。
逐题比较答案质量、证据覆盖、通信字节与 token、调用与耗时，以及关键证据误删。
汇总后删除只能证明中心上下文减少；上行流量收益必须由发送前的选择机制及完整协商成本验证。

## 完成条件
1. 一个数据源小样本通过同步与证据可核查性检查。
2. 输入、端消息、中心答案和成本能完整回溯。
3. 有人工核查的重复、互补和独立确认案例。
4. 完成配对对照和失败案例分析，明确下一步。
5. 正式扩大前确定质量损失容忍度、预算、样本划分与评价规则。

不预填准确率、节省比例或未经测量的实验结论。
