# 目录与存储约定

## GitHub 保存什么
- docs/：计划、决策、实现说明和结果解释。新决定记录日期、理由和影响。
- configs/：模型、提示词、抽帧、生成、通信策略和随机种子等实验配置；机器路径放 *.local.yaml，凭据通过环境变量提供。
- data/manifests/：样本清单、划分、数据版本、校验值；不提交原始视频。数据访问和标注共享遵循原数据条件。
- data/reading_library/：论文索引 CSV 与逐篇 Markdown 研究卡片；一篇论文一行索引，卡片记录自己的总结、实验依据、局限和研究启发。
- src/：后续建议按 datasets、endpoints、evidence、communication、aggregation、evaluation 拆分；有实际实现再建立模块。
- scripts/：运行、检查和结果导出入口，注明在哪个工作目录执行。
- tests/：对数据同步、证据映射、成本计量等关键行为进行必要测试。
- results/：人工选择并检查后的运行记录、指标、报告与小型逐题结果。

## 外部存储保存什么
原始视频、模型权重、特征、缓存、完整原始日志和大型逐题输出存放在服务器或其它持久存储。artifacts/ 是本地入口，不会随 Git 同步。
每次运行通过 artifacts.json 记录相对位置或持久存储地址、校验值和大小；不要只给其它机器无法访问的绝对路径，也不要提交含凭据的地址。

## 建议命名
- 实验编号：EXP-001，例如“首轮现象验证”。
- 运行编号：20261023T153000+0800_baseline_seed0；记录时区，重跑使用新编号。
- 一个运行目录只代表一次执行；失败或中断也保留状态，不覆盖旧结果。
- 同一实验的多个条件必须能对应到相同样本与评价规则。

## 小型文件与大文件
results/ 默认可提交，但必须人工挑选。建议单个文本结果超过 10 MiB 时拆分或放外部存储，并提交索引；这只是项目建议，不是 GitHub 配额说明。
图片选择必要的报告图表，完整中间产物留在外部。不要把不进 Git 误当成已备份。
